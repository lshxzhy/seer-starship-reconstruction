# SEER 系统逻辑与开发交接

玩家操作见[项目首页](../README.md)，未完事项见[开发路线](ROADMAP.md)。修改源码后在仓库根目录运行 `python work/assemble-seer.py`。本机服务和聊天打包读取 `work/seer-fragment.html`，单文件游玩读取 `outputs/seer-starship.html`。发布的源码运行包从对应 Git 提交导出。早期整份脚本副本已退出默认构建。

## 界面、控制器与持久化

`src/viewer/explore.js` 切换舰内、舰体观察和行星场景，连接舰载终端、精灵终端和飞行控制器。输入由当前场景接收。打开地图、背包或精灵面板时，各面板处理自己的键盘焦点；关闭后还给操作入口。主要流程如下。

| 玩家动作 | 谁决定结果 | 保存什么 |
|---|---|---|
| 看轨道、查地点、步行或人员传送 | 舰图与地表图读取同一份地点索引；`explore.js` 和 `expedition.js` 切换人员位置 | 当前场景、所在星、脚点与路线；L-01 的停放位置另存 |
| 乘廊车、驾驶、在另一颗星着陆 | 机位给出泊位，`pano-transfer.js` 做星际积分，`shuttle-flight.js` 管近地操纵与起落 | 原机位、参考星、位置、速度、姿态、模拟时钟和目标 |
| 采训练矿、动力室分批交付 | `boarding.js` 核对实际站位、装备和数量；`locker-record.js` 归并已采和已交的份额 | 钻头、剩余矿样、交付批次，按收据计算收益 |
| 接触精灵、捕猎、首胜、培养 | 精灵终端发送动作，`system.js`、`safari-rules.js` 结算；成功写入才更新地表目标或奖励 | 个体、队伍、仓库、回合、首胜、物资、捕猎和孵化截止时间 |
| 与船员或精灵交谈 | `dialogue.js` 将联系人和当前场景交给本机 `server.py`，服务从名册与图鉴组装模型上下文 | 对话按人物或精灵个体在当前页面保留；对话无库存和任务写入接口 |

航程、舰内物资与精灵各有存档。聊天版经原宿主恢复状态，单文件游戏经外层页面保存，本机通讯版保存到同源浏览器。精灵写入使用修订号处理并发，导入失败时保留原队伍。旧船上物资记录由 `normalizePilotPack` 迁移，早期单星航程默认归入克洛斯星；详见[精灵存档与规则](精灵系统.md)及[跨星航行](帕诺轨道与海洋星.md)。

## 行星与实体尺寸

球半径集中在 KLOSE_WORLD 与 OCEAN_WORLD。星图轨道由独立的 PANO_ORBITS 管理。地表的经典区、船尾坡和步行路线以米表示。地表飞行的接近范围随球半径变化，母舰随克洛斯星公转，接近原泊位时恢复舰侧操纵。[航程版本迁移](../src/galaxy/voyage-scale.js) · [跨星飞控](../src/galaxy/pano-transfer.js)

航程的行星记录格式和艇记录均升至 3，外层存档沿用原键。读取版本 2 时，映射地表脚点、地标、停艇和尾坡；星际段保留时间和参考系坐标。在原机位旁用旧泊位坐标系转回当前机位。读取新格式时直接使用当前坐标。精灵队伍、背包和兑换收据有各自的存储入口。

地表及随行精灵统一由 `createFieldSpirit` 用图鉴厘米值、模型包围盒和 1.65 倍世界比例计算一次实际尺寸。交互、镜头、阴影和避碰读取该实体的身高或半径。图鉴和对战共用对应模型，保留各自的取景；资料身高、等级和战斗数值沿用原数据。[模型入口](../src/spirits/partner-figures.js) · [野外与随行](../src/spirits/escort.js)

## 舰内空间、角色和运输

- **总体与专业舱室。** `src/ship/` 管舰壳、内层和涂装。`src/habitat/installation.js` 给出十一舱、公共通道和四层驻舱的米制坐标；`layout-record.js` 输出同一套安装表。公共舱改 `civic.js`，机务舱改 `engineering.js`，科研指挥舱改 `science.js`。新舱沿用稳定 ID，局部原点设在地面中心，Y 向上、+Z 指门口；大件在 `kit.block` 登记占地，公共门净宽 3.4 米、高 3.1 米。[原作来源](SOURCES.md)
- **两条升降线与四个登艇机位。** 实体门、井道和轿体在 `lift-plant.js`，站表和运行在 `lift-ride.js`。玩家、镜头和伙伴同乘轿厢。机位触发与地面亮框来自同一份 `civic.js` 配置，舱内装置在 `transporter.js`，返程使用出发泊位。[舰内升降](舰内升降系统.md) · [传送舱接口](舰内传送舱接口.md)
- **路标与采样。** `wayfinding.js` 把路线接到舱门、走廊和候梯区。`exchange.js` 显示操作，机械室与动力室分别提供矿架和投入口。训练矿样、精灵奖励黑晶矿与星球上的矿物地标用途不同。[原版兑换及项目结算](动力室物资兑换图证.md)
- **玩家与船员。** `src/population/robot.js` 定义共用机体、屏面、步态和第一人称眼位，玩家由 `player.js` 驱动，驻舱与近场船员由 `berths.js`、`population.js` 管理。NoNo 用 `super-nono.js`；奥飞滑翔翼的踏面、机身与驾驶包络分别在 `personal-flyer.js`、`personal-flight.js`。门洞、碰撞宽度、玩家脚底和载具踏面必须用同一米制基准。[面盘](面盘表情图证.md) · [NoNo](超能NoNo图证.md) · [滑翔翼](单人飞行器图证.md)

## 人员移动与工位交互

舰内、艇内、地表共用玩家的朝向换算和步速，步行 4.4、快跑 8.4 米/秒，斜向输入作单位化。地表脚点按小步长扫过障碍，步态与面向取实际位移，靠原艇可沿外壳滑动或从开启的尾坡登艇。队伍随行会先转向再追赶，深水区游动精灵遇阻时会减速、转身重选巡游方向。观察精灵使用独立的绕行角和距离，离开观察时沿用原步行视角。[玩家步速](../src/viewer/walking.js) · [地表输入与相机](../src/galaxy/expedition.js)

具名实体的部件、图像编号和舱内工位在 `src/population/named-crew.js`。人物不另占新名额。人口系统从现有值班员记录提供 `characterId` 和近场碰撞，现场卡片由 `characters.json` 的公开事实随构建产生。本机通讯使用同一个 ID，普通船员继续按 SE 编号联系。第一人称靠近具名舰员时，NoNo 根据玩家和对方面盘的位置选择可通行的侧后方随行位。奥飞与 L-01 的推进、制动和速度包络由各自飞控模块管理。[舰上组织](舰上组织与角色.md) · [滑翔翼](单人飞行器图证.md) · [登陆艇](载人登陆艇.md)

## 星际飞行与地表导航

`klose-map.js` 建立地点、着陆点、步行连接和飞行目标；`pano-system.js` 注册两颗行星，并通过同一个 `panoCenter` 计算二维轨道和三维日心位置。区域页的步行目的地与驾驶席的航点有不同用途。以海洋星为例，`ocean-shallows` 在地表索引指浅水区，在飞行索引指浅海登陆平台；人员直达平台使用 `ocean-shallows-pad`。原艇尾坡根据停放星球和实时艇姿另行计算。地图预览只读索引、投影和泊位坐标，进入航行或地表时才创建三维场景。

`carrier-dock.js` 安装原母舰泊位与接驳廊车。`landing-shuttle.js` 管同一艘 L-01 的艇壳、尾坡、座椅、三组舷窗和驾驶台，米制布局同时供步行、上下艇和驾驶相机使用。驾驶屏读取真实状态，实体键转发同一套航线与飞控操作。修改尾坡、机翼或起落脚时要兼顾停靠净空和下船通路。[登艇与驾驶](载人登陆艇.md)

克洛斯星由 `klose-surface.js`、`klose-scenery.js`、`klose-creatures.js` 和 `klose-safari.js` 管球面、地貌和实体；皮皮的模型前向为局部 +Z。海洋星在 `ocean-surface.js` 管连续海床、平台和镜头避障，`ocean-ecology.js` 管水下精灵。跟随者在两星使用所在星体的半径。[克洛斯星分布](克洛斯星精灵图鉴.md) · [海洋星四区](帕诺轨道与海洋星.md)

## 精灵与本机模型

`src/spirits/catalog.json` 是游戏和本机服务共读的图鉴快照。物种编号、持有个体 UID 和现场遭遇键分别标识三个对象。每次捕捉要同时处理个体去向、胶囊消耗和遭遇结束；六位队伍已满则入仓。`createCompanionFigure` 为图鉴、回合战和随行提供同一三维入口。

`challenges.js` 登记两位 SPT 首领的地点、等级、专属体力和首胜奖励。SPT 卡片、野外首领生成、对战和存档读取均使用对应记录。精灵背包里的同种个体按个体值计算能力。湿地场次的专用胶囊、鱼竿和截止时间由 `safari-rules.js` 结算，不能用普通战斗的胶囊扣费。黄金布布的孵化有单独的现实时间记录。[系统规则](精灵系统.md)

角色名册在 `src/ai/characters.json`。具名角色用稳定 ID，普通船员按 SE 编号区分，精灵区分野生、持有和图鉴模拟。名册的 `facts`、`sources` 记录出处，`persona`、`expertise` 保存项目演绎。启动本机通讯后才请求本机 Ollama，默认模型 `qwen3.5:9b`，思考关闭。[舰上组织与角色](舰上组织与角色.md)
